# Novel2ScriptAl 剧本 YAML Schema 定义文档

> 版本：1.0 | 最后更新：2026-06-07

---

## 一、Schema 设计目标

本 Schema 是将小说文本转换为结构化剧本的中间数据格式。设计时遵循三个原则：

1. **行业兼容性**：字段映射 Final Draft 等行业标准，确保可导出为 `.fdx` 被专业编剧软件识别
2. **AI 可生成性**：结构足够明确，大语言模型可稳定输出合法 YAML，字段枚举约束减少幻觉
3. **人类可读性**：层级清晰，编剧可直接阅读修改，无需特殊工具

---

## 二、完整 Schema

```yaml
# ============================================================
# 顶层结构
# ============================================================
title: string              # 必填。剧本标题，从原文提取或 AI 概括
genre: string              # 必填。类型标签，如"文艺/剧情""悬疑/推理"
logline: string            # 必填。一句话故事梗概（30-80 字）
version: string            # 必填。版本号，如"1.0"
author: string             # 必填。作者署名，默认为"AI 编剧"
language: string           # 必填。语言代码，如"zh-CN""en-US"

# ============================================================
# 角色表
# ============================================================
characters:
  - char_id: string        # 必填。唯一标识，格式 C + 两位数字，如 C01
    name: string           # 必填。角色名称
    description: string    # 必填。一句话角色描述
    traits:                # 必填。性格特质数组，2-5 个标签
      - string

# ============================================================
# 场景列表
# ============================================================
scenes:
  - scene_id: string       # 必填。唯一标识，格式 S + 两位数字，如 S01
    location: string       # 必填。格式"内·场地名"或"外·场地名"
    time: enum             # 必填。枚举：白天 | 夜晚 | 黄昏 | 凌晨
    chapter_index: integer # 必填。所属章节序号，无章节则为 1
    chapter_title: string  # 必填。章节标题，无章节则为"正文"
    scene_tag:             # 必填。场景标签数组
      - string
    shot_remark: string    # 必填。拍摄备注（运镜、光影要求），可为空字符串
    characters_in_scene:   # 必填。出场角色 char_id 列表
      - string
    content:               # 必填。内容数组，严格仅两类 type
      - type: enum         # 必填。action | dialogue
        # --- type=action 时 ---
        text: string       # 必填。动作、环境、神态描述
        # --- type=dialogue 时 ---
        char_id: string    # 必填。说话角色 char_id
        mood: string       # 必填。台词情绪，如"平静""愤怒""微笑"
        text: string       # 必填。台词文本

    # ======== 可选字段（add_mood=true 时由 AI 生成）========
    mood: string             # 可选。场景整体情绪标签
    suggested_lighting: string  # 可选。建议灯光方案
    suggested_sound: string     # 可选。建议音效/配乐方案
```

## 三、字段详细说明

### 3.1 顶层元数据

| 字段 | 类型 | 约束 | 设计原因 |
|------|------|------|---------|
| `title` | string | 非空 | 剧本基本标识，导出 TXT/FDX 时用作文件名和标题页 |
| `genre` | string | 非空 | 便于编剧软件分类检索，下游可按类型筛选 |
| `logline` | string | 30-80 字 | 行业标准字段，制片方快速判断剧本价值 |
| `version` | string | 语义化版本 | 支持多次修改的版本追踪 |
| `author` | string | 非空 | 版权标识，AI 生成标注"AI 编剧" |
| `language` | string | ISO 639-1 | 支持多语言扩展，当前为 zh-CN |

### 3.2 角色表 (characters)

设计为**独立顶层数组**而非嵌入场景中，原因：

- **引用复用**：scene 通过 `char_id` 引用，避免每个场景重复角色信息
- **编剧工作流**：编剧通常先整理角色表再分场写作，此结构匹配创作习惯
- **校验方便**：角色一致性校验直接读取 `characters` 与 `dialogues` 比对

| 字段 | 类型 | 设计原因 |
|------|------|---------|
| `char_id` | C + 数字 | 短标识便于对话区引用，避免同名歧义 |
| `name` | string | 显示名称 |
| `description` | string | 一句话描述便于 AI 和人类理解角色定位 |
| `traits` | string[] | 结构化标签（如"内敛""念旧"），支持角色一致性校验的自动比对 |

### 3.3 场景 (scenes)

#### scene_id

格式 `S01`、`S02`... 而非纯数字 `1`、`2`。

- **原因**：在 YAML 中 `S01` 始终为字符串类型，避免 YAML 解析器将 `1` 解析为整数导致类型不一致。同时 `S` 前缀在脚本讨论中可直接作为场景代号使用（"我们看下 S03"）。

#### location

格式 `内·咖啡厅` 或 `外·公园`，用中点 `·` 分隔内外标识与场地名。

- **原因**：中文剧本行业惯用"内景/外景"标识。`·` 分隔符比 `-` 更视觉清晰，同时保持可搜索性（搜"内·"即得所有内景）。

#### time

枚举 `白天 | 夜晚 | 黄昏 | 凌晨`。

- **原因**：限定枚举避免 AI 生成"傍晚""清晨"等近义词导致下游处理混乱。四个值覆盖全部日光周期，与 Final Draft 的 Day/Night/Dawn/Dusk 对应。

#### chapter_index / chapter_title

- **设计原因**：小说改剧本通常需要保留原文章节结构。输出时将章节信息平铺到每个 scene 中而非嵌套 `chapters` 对象，因为：YAML 中嵌套层级越深，AI 越容易生成错误缩进；平铺后前端表格可直接按 `chapter_index` 分组排序。

#### scene_tag

字符串数组，如 `[重逢, 怀旧, 冲突]`。

- **原因**：情绪和剧情类型的轻量标注，便于前端展示彩色标签、按标签筛选场景。

#### shot_remark

自由文本字段，可包含运镜建议、光影要求、特效备注。

- **原因**：与 Final Draft 的 Shot/Transition 元素对应，导出 FDX 时映射为 `Paragraph Type="Shot"`。

#### characters_in_scene

出场角色 char_id 数组。

- **原因**：便于场记快速确认本场演员、前端可展示"本场角色"缩略头像。角色校验时也直接读取此字段。

### 3.4 content 数组（核心创新）

`content` 采用**扁平数组 + type 字段**而非传统剧本格式的 `action` / `dialogues` 分块。原因：

1. **保留时序**：小说改编中，动作和对话交替出现（"他推门→说你好→坐下→服务生过来→点单"），`content` 数组按时间顺序排列，精确还原原文节奏
2. **单一数据源**：前端渲染剧本时遍历一个数组即可，无需合并两个独立列表
3. **AI 友好**：LLM 以流式方式生成内容，按事件顺序输出比预分类再填充更自然，减少结构错误
4. **扩展性**：未来如需添加 `type: monologue`（独白）或 `type: voiceover`（画外音），只需新增 type 值

#### type: action

| 字段 | 说明 |
|------|------|
| `text` | 人物动作、环境描写、场景状态、肢体神态细节 |

#### type: dialogue

| 字段 | 类型 | 说明 |
|------|------|------|
| `char_id` | string | 说话角色的 char_id，关联 characters 表 |
| `mood` | string | **台词级情绪**（区别于 scene 级 mood）。如"微笑""咬牙切齿""低声"，这是原版 Schema 中常被忽略但对表演指导至关重要的字段 |
| `text` | string | 台词文本 |

### 3.5 可选 mood 字段

当用户勾选"情感标签"（`add_mood=true`）时，每个 scene 额外包含：

| 字段 | 说明 |
|------|------|
| `mood` | 场景整体情绪（如"温馨""紧张""诡异"） |
| `suggested_lighting` | 灯光建议（如"暖黄顶光""冷蓝侧光"） |
| `suggested_sound` | 音效/配乐建议（如"雨声白噪""低沉弦乐"） |

## 四、设计决策汇总

| 决策 | 理由 |
|------|------|
| `content` 数组替代独立 `action`/`dialogues` | 保留时序、AI 友好、单一渲染源 |
| `scene_id` 用 `S01` 而非 `1` | 防止 YAML 类型歧义，方便口头引用 |
| `time` 限制 4 个枚举值 | 防止 AI 幻觉近义词，对齐 Final Draft |
| 角色表独立于场景 | 复用引用、匹配编剧工作流 |
| `chapter` 平铺到 scene 中 | 减少 YAML 嵌套深度，便于前端分组 |
| 台词级 `mood` + 场景级 `mood` 并存 | 粒度不同：一场戏的整体基调 vs 单句台词的情绪 |
| `char_id` 而非角色名用于 dialogue | 唯一标识，避免同名歧义，校验时精确匹配 |

## 五、Schema 演进规划

| 版本 | 计划 |
|------|------|
| 1.0（当前） | 基础字段 + content 数组 + mood 可选 |
| 1.1（规划） | 支持 `type: monologue`（独白）、`type: voiceover`（画外音） |
